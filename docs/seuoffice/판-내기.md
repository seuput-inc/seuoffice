# 판 내기

seuoffice는 판 하나에 데스크톱 앱과 웹 묶음을 함께 낸다. 둘 다 GitHub 릴리스에 붙고, npm 저장소에는 올리지 않는다(결정 0021).

## 내는 것

| 파일                                                      | 내용                                                                                                                                                                               |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SeuOffice-Setup-<판>.exe`, `SeuOffice-<판>-arm64.dmg` 등 | 데스크톱 앱. 설치본은 스스로 업데이트한다(결정 0013, 0020)                                                                                                                         |
| `seuoffice-embed-<판>.tgz`                                | 호스트 쪽 라이브러리 `@seuoffice/embed`(`openDocument`). 빌드한 ESM JS와 `.d.ts`                                                                                                   |
| `seuoffice-web-<판>.tgz`                                  | 빌드한 정적 웹 묶음 `@seuoffice/web`(`dist/`). 호스트가 한 주소 아래 그대로 서빙한다                                                                                               |
| `seuoffice-collab-<판>.tgz`                               | 공동 편집 서버와 엔진 `@seuoffice/collab`(`/server`, `/client`, `/conformance`). 호스트 백엔드가 `/server`를 쓴다. 웹 묶음에는 엔진이 이미 들어 있다([공동-편집.md](공동-편집.md)) |
| `seuoffice-history-renderer-<판>.tgz`                     | 보관한 원본과 확정 이력으로 서버에서 파일을 만드는 `@seuoffice/history-renderer`(`renderBytes`). [지원 형식과 실행 환경](../../packages/history-renderer/README.md)                |

네 묶음은 같은 워크플로 실행의 커밋과 판 번호를 쓴다. 워크플로가 포장 전에 네 `package.json`의 판 번호와 렌더러의 `@seuoffice/collab` 의존성을 그 판으로 고정한다. 개발용 번호와 잠금 파일은 바꾸어 커밋하지 않는다. `@seuoffice/web-platform`은 웹 묶음 안에 들어가는 내부 부품이라 따로 내지 않는다. 이미 게시한 태그에 렌더러를 소급해 붙이지 않는다.

저장소 안에서는 `@seuoffice/embed`가 소스(`src/index.ts`)로 풀린다. `package.json`의 `exports`에 `seuoffice-source` 조건을 두었고, `apps/web`의 `tsconfig.json`(`customConditions`)과 `vite.config.ts`(`resolve.conditions`)가 그 조건을 켠다. 외부 소비자는 그 조건을 모르므로 `dist`를 받는다.

## 판이 나오는 법

판은 모아서 낸다(결정 0027). `main`에 푸시해도 판은 나오지 않는다.

1. 합친 변경이 한 묶음이 되면 메인 세션이 판을 시작한다. 사용자에게 보이는 변화가 있을 때만 낸다. 보안 결함, 문서를 잃거나 망가뜨리는 결함, 앱이 켜지지 않거나 업데이트가 안 되는 결함만 고친 즉시 낸다.

   먼저 다음 판의 노트를 `docs/seuoffice/판-노트/<판 번호>.md`에 쓰고 `main`에 올린다. 업데이트 창이 릴리스 본문을 그대로 보여 주므로, 노트는 사용자가 느끼는 바뀐 점만 `- ` 항목 1~6개로 쓴다(사용자 말로, 커밋 말투·내부 번호·코드 표기 없이). 서명 없는 판을 처음 여는 법은 README의 내려받기 절에 있고 본문에는 넣지 않는다. `node tools/check-release-notes.mjs <판 번호>`가 노트를 검사하고, 릴리스 작업은 빌드 전에 같은 검사를 돌려 노트가 없거나 맞지 않으면 멈춘다. 이미 낸 판의 노트를 고치려면 `gh release edit v<판 번호> --notes-file <파일>`로 본문만 바꾼다. 앱은 켤 때와 1시간마다 피드를 다시 읽으므로 그다음 확인부터 새 본문이 보인다.

   ```sh
   gh workflow run "seuoffice desktop release" --ref main -f release=true
   ```

   `.github/workflows/seuoffice-desktop.yml`이 다음 판 번호로 앱과 웹 묶음을 빌드하고, 같은 커밋의 `CI`와 `seuoffice`가 둘 다 녹색이면 미리보기 판(pre-release)을 낸다(결정 0020, 0027). `v<판 번호>` 태그를 손으로 밀어도 그 판으로 같은 일을 한다.

   정식으로 올리기 전에 직전 정식 판에서 새 판으로 앱 안 업데이트가 되는지 러너에서 확인한다(`seuoffice migration`, 시험 프로필과 합성 자료만).

   Rust 셸(Tauri 2)의 첫 판부터는 후보 빌드, 이행 시험, 후보 게시의 세 단계를 거친다. 그 절차와 남은 관문은 [3단계-첫-판-관문.md](3단계-첫-판-관문.md)에 있고, 셸이 main에 합쳐질 때 이 절에 옮긴다.

2. 메인 세션이 판을 안정 판으로 올린다. 판을 내고 올리는 데 스풋의 승인은 받지 않는다(2026-11-13 스풋). 올린 뒤 바뀌는 점(사용자가 느끼는 것, 라이선스 문구, 업데이트로 바뀌는 것)을 문의 탭에 한 단락으로 보낸다. 승인 요청이 아니다.

   ```sh
   gh release edit v0.12.43 --prerelease=false --latest
   ```

판을 낸 실행은 성공한 뒤에 `scripts/release-prune.sh`로 오래된 릴리스를 지운다. GitHub가 Latest로 표시한 판, 정식 최신 3개, 프리릴리스 최신 3개, `.github/release-keep.json`에 이유와 함께 적은 판은 남기고, 태그는 지우지 않는다. 붙이는 쪽(YUYU 등)이 고정해 쓰는 판은 keep 목록에 적는다.

이번 게시에서 과거 릴리스와 첨부를 **모두 보존**하려면 아래처럼 실행한다. 게시 후 정리 대상은 출력하지만, 확인했던 목록과 달라져도 하나도 지우지 않는다. 이 입력은 이번 수동 실행에만 적용된다. `false`로 두거나 생략한 수동 실행과 태그 푸시는 기존 정리 규칙을 따른다.

```sh
gh workflow run "seuoffice desktop release" --ref main -f release=true -f preserve_old_releases=true
```

## 내기 전에 손으로 확인하기

```sh
npm run build:wasm
npm run build -w @seuoffice/web
npm pack --dry-run -w @seuoffice/embed -w @seuoffice/collab -w @seuoffice/web
npm pack --dry-run -w @seuoffice/history-renderer
```

- `embed`에는 `dist/index.js`와 선언 파일, `collab`에는 서버·클라이언트·시험 도구 진입점과 선언 파일이 있어야 한다.
- `web`에는 `dist/index.html`과 `THIRD-PARTY-NOTICES.txt`가 있어야 한다. `web`을 먼저 포장해야 렌더러가 같은 빌드의 WASM 고지를 복사할 수 있다.
- 렌더러에는 `dist/index.js`, `index.d.ts`, 격리 실행 번들, `dist/THIRD-PARTY-NOTICES.txt`와 `dist/OFFICE-WASM-NOTICES.txt`가 있어야 한다. 네 묶음 모두 저장소의 `LICENSE`, `LICENSE-APACHE`, `NOTICE`를 담는다.

## 붙이는 쪽이 받는 법

붙이는 쪽은 안정 판 하나를 골라 두 묶음을 그 판의 릴리스 주소로 설치한다. 두 묶음은 같은 판을 쓴다.

```sh
npm install \
  https://github.com/seuput-inc/seuoffice/releases/download/v0.12.15/seuoffice-embed-0.12.15.tgz \
  https://github.com/seuput-inc/seuoffice/releases/download/v0.12.15/seuoffice-web-0.12.15.tgz
```

`package.json`에는 주소가 그대로 적히고, `package-lock.json`이 파일의 해시를 고정한다. 판을 바꾸려면 주소의 판 번호만 바꿔 다시 설치한다. 설치에 npm 계정이나 토큰은 필요 없다.

`@seuoffice/web`의 `dist/`는 붙이는 쪽 빌드 과정에서 정적 경로(예: `public/seuoffice/`)로 복사해 서빙하고, 그 주소를 `openDocument`의 `baseUrl`로 넘긴다. 서빙하는 웹 묶음과 호스트 코드가 다른 판이 되면 안 되므로 두 주소를 같이 바꾼다.

웹 묶음을 붙이는 페이지와 다른 출처에 올리면(권장), 그 출처의 `dist/` 루트에 허용할 붙이는 쪽 출처를 적은 `embed-origins.json`을 둔다. 형식과 iframe `sandbox` 기본값은 `packages/embed/README.md`에 있다.

### 이력 렌더러를 포함한 판 확인

호스트는 렌더러를 포함한 판의 태그(`TAG`, 앞에 `v` 포함)와 승인한 전체 커밋 SHA(`EXPECTED_COMMIT`)를 고정한다. 다음 명령은 해당 소스 체크아웃에서 실행한다. `gh`, `jq`, `shasum`이 필요하다.

```bash
set -euo pipefail
: "${TAG:?판 태그 필요}" "${EXPECTED_COMMIT:?승인한 커밋 필요}"
repo=seuput-inc/seuoffice
test "$(gh api "repos/$repo/commits/$TAG" --jq .sha)" = "$EXPECTED_COMMIT"
out=$(mktemp -d)
gh release download "$TAG" --repo "$repo" --dir "$out" --pattern "seuoffice-*-${TAG#v}.tgz"
gh api "repos/$repo/releases/tags/$TAG" | bash scripts/verify-web-release-assets.sh "$TAG" "$out"
```

검사는 **그 태그의 GitHub Release API가 돌려준 `assets[].digest`**와 내려받은 네 파일의 SHA-256을 이름별로 대조한다. 하나라도 없거나 다르면 설치하지 않는다. Actions 작업 산출물의 해시, 로컬 시험 포장 해시, npm 잠금 파일은 공식 자산 digest를 대신하지 않는다. 서버에는 검사를 통과한 같은 판의 `collab`과 `history-renderer`를 함께 설치한다. 브라우저 전용 호스트에는 렌더러가 필요 없다.

### 판 올리기

1. 붙이는 쪽 저장소에 `chore(seuoffice): 0.12.15 -> 0.12.16` 같은 판 올리기 커밋을 만든다. 이 커밋은 `package.json`의 두 주소, 잠금 파일, 복사해 둔 웹 묶음만 바꾼다. 다른 변경을 섞지 않는다.
2. 그 판의 릴리스 본문과 seuoffice 저장소 `docs/seuoffice/`의 로드맵에서 바뀐 동작을 읽고, 붙이는 쪽이 쓰는 곳(열기, 편집 잠금, 저장 처리)에 영향이 있는지 본다.
3. 배포 전 검사를 돌린다. 붙이는 쪽이 쓰는 형식(docx, xlsx, pptx, pdf, hwp, hwpx)의 모의 문서를 열고, 편집 모드로 고쳐 저장한 바이트가 호스트에 저장되는지 확인한다. 실데이터는 쓰지 않는다.
4. 검사가 통과하면 운영에 넣는다. 문제가 있으면 판 올리기 커밋만 되돌린다.
