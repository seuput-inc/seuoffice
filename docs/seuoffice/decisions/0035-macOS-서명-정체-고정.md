# 0035 macOS 앱은 자체 서명 인증서 하나로 서명 정체를 고정한다

- 날짜: 2026-11-17
- 상태: 확정, 구현 중
- 결정한 사람: 전체관리 세션이 승인했고(2026-11-17, 스풋에게 알림), 메인 세션이 구현한다.
- 보완하는 것: 결정 0013의 "서명 없이 운영한다". 0013의 뜻은 그대로다. 유료 Apple 서명(Developer ID, 공증)을 쓰지 않고, Gatekeeper 안내와 설치 절차도 지금과 같다.

## 맥락

macOS 키체인 항목의 접근 목록은 항목을 만든 앱의 서명 요구 조건에 묶인다. 지금 판은 ad hoc 서명이라 요구 조건이 실행 파일의 해시(cdhash)다. 판이 바뀔 때마다 해시가 바뀌므로, AI 키를 처음 읽을 때마다 "항상 허용" 대화상자가 뜬다(결정 0029 (b), 0033 3항). 사람이 누를 수 없는 러너에서는 AI 키 이행 시험이 대화상자에서 멈춘다.

결정 0029 (b)는 대화상자를 없애는 길 둘을 증명했다. 마지막 Electron 판이 값을 열어 새 껍데기를 `-T`로 올려 다시 봉하는 길(R1)과, 같은 서명 인증서로 서명하는 길(R4, R5)이다. 자체 서명 인증서로도 됐다.

## 결정

1. **Mac 앱은 자체 서명 인증서 하나로 서명한다.** 인증서는 무료로 만든 자체 서명 코드 서명 인증서다(이름 `SeuOffice Self Sign`, 유효 기간 20년). 판마다 같은 인증서로 서명하므로 서명 요구 조건(번들 ID와 인증서)이 판끼리 같고, 판끼리의 업데이트에서 키체인 대화상자가 뜨지 않는다.
2. **Apple 신뢰 서명이 아니다.** Gatekeeper는 지금처럼 처음 열 때 막고, 사용자는 "그래도 열기"를 누른다. 판 노트의 설치 안내는 그대로다. 앱 안 업데이트(zip을 풀어 바꿔 끼우기)는 `codesign --verify --deep --strict`만 보므로 자체 서명으로도 돈다.
3. **개인 키는 GitHub Actions 비밀값에만 둔다.** 이름은 `MAC_SELF_SIGN_P12`(p12의 base64)와 `MAC_SELF_SIGN_PASSWORD`다. 키는 만들 때부터 대화·로그·저장소 파일에 나오지 않게 하고, 워크플로는 값을 출력하지 않는다. 비밀값을 쓰는 작업은 이 저장소의 push, 태그, `workflow_dispatch`에서만 돈다. 포크에서 온 `pull_request`에서는 돌지 않고, `pull_request_target`은 쓰지 않는다.
4. **키 사본은 맥미니 로그인 키체인에 둔다.** 위치 이름: 맥미니 `choejinseo` 계정 로그인 키체인의 인증서 항목 `SeuOffice Self Sign`(개인 키 포함)과 p12 암호 항목 `SeuOffice Self Sign p12`. 저장소, Home Repo, 채팅에는 두지 않는다. 사본까지 잃으면 새 인증서를 만들고, 그 판으로 넘어갈 때 대화상자가 한 번 뜬다는 것을 판 노트에 적는다(`판-내기.md`).
5. **기존 사용자는 한 번 본다.** 옛 ad hoc 판이 봉한 항목은 옛 해시에 묶여 있어서, 정체를 고정한 첫 판으로 넘어갈 때 대화상자가 한 번 뜬다. R1도 마지막 Electron 판이 그 항목을 여는 순간 같은 대화상자를 만나므로 0번으로 만들 수 없다. 첫 판의 판 노트에 미리 알린다.

## 버린 대안

- **R1만 쓴다.** 넘어가는 한 번만 없애고(그마저 위 5항 때문에 남는다), Tauri 판끼리의 업데이트마다 대화상자가 다시 뜬다.
- **Developer ID로 서명하고 공증한다.** 유료이고, 결정 0013의 "서명 없이 운영"을 바꾼다. 서명된 판이 한 번 나가면 되돌릴 수 없다.
- **지금처럼 ad hoc로 둔다.** 업데이트마다 대화상자가 뜨고, 러너에서 AI 키 이행을 사람 없이 확인할 수 없다.

## 결과

판끼리의 업데이트에서 키체인 대화상자가 없어지고, 러너가 Tauri 판끼리의 업데이트에서 AI 키가 그대로인지 사람 없이 확인한다. Electron 판에서 첫 Tauri 판으로 넘어가는 한 번의 대화상자는 남는다. 인증서 개인 키를 지키는 일이 새로 생긴다.
