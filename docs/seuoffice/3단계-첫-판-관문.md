# 3단계 첫 판까지 남은 관문

- 처음 쓴 날: 2026-11-17
- 근거: 결정 [0034](decisions/0034-안정-Tauri2-셸.md), 3단계 넘어가기 시험(`3단계-넘어가기-시험.md`, 껍데기 가지와 함께 들어옴), [판 내기](판-내기.md)

관문은 아래 순서로 지난다. 앞 관문이 녹색이어야 다음 관문의 결과를 믿는다. 관문을 지나려고 시험을 줄이거나 바닥값을 낮추거나 차이를 기록에 숨기지 않는다. 사람이 손으로 하던 확인은 없애지 않고 같은 것을 자동 시험으로 확인한다. G3과 G6은 GitHub 러너와 맥미니의 시험 프로필·임시 자료 폴더에서만 돌리고, 스풋의 기기·설치본·프로필·키체인 항목은 쓰지 않는다.

## native 전용 IPC 채널의 실제 앱 증거(설계, 아직 구현하지 않음)

Electron 쪽 핸들러가 없는 14개 채널(`tools/shell-inventory/native-channels.ts`)은 Electron과 비교할 수 없다. `seuoffice rust`의 IPC 비교는 채널마다 두 증거를 요구한다. 합성 증거(`synthetic`)는 `native_evidence_` Rust 시험이 핸들러를 시나리오대로 돌리고 모든 단언이 통과한 뒤에만 영수증을 쓴다(`shell_contract::native_evidence`, 워크플로의 "Native synthetic evidence" 단계). 실제 앱 증거(`native-host`)는 아래 설계대로 G3의 실제 앱 실행에서 얻는다. 시험 소스나 설계 문서는 영수증이 아니다.

**실행.** `seuoffice shell` `gate=e2e`(`crates/shell/src/e2e`, `--e2e <scenario.json> --out <dir>`)에 시나리오를 더한다. 실행기에는 두 가지를 더한다.

- 복구 시나리오는 두 번 실행한다. 1차 실행은 편집 뒤 새 작업 `crash`로 앱을 비정상 종료한다. 2차 실행은 같은 시험 프로필로 다시 띄워 복구 대화상자에 `restore`로 답한다. 복구본은 앱이 스스로 남긴 것만 쓴다.
- 사용자가 낼 수 없는 거절 경로(가짜·남의 토큰, 다른 화면, 중복 응답)는 새 작업 `invoke`로 만든다. 활성 페이지의 preload 다리로 그 채널을 실제 웹뷰에서 부르고, 답이나 오류를 기록한다. 새 IPC 채널은 만들지 않는다.

| 채널                                                         | 실행할 시나리오                                                                                       | 실제 앱에서 보는 시나리오                                                                                                                                 |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `docs:owned-print-pdf-buffer`                                | `docs-quit`의 PDF 저장 변형                                                                           | 닫기 저장의 PDF 내보내기가 끝남(normal-completion), 쓸 수 없는 폴더(effect-failure), 내보내기 중 탭 닫기(owner-loss), `invoke`로 토큰 없음·남의 토큰·다른 화면 |
| `pdf:consume-recovery-pending`, `pdf:recovery-initialized`   | `pdf-view` 복구 변형(주석 뒤 `crash`, 2차 `restore`)                                                  | 일반 열기의 빈 답, 복구본 소비와 적용 뒤 응답(renderer-apply), `invoke`로 중복 소비·중복 응답·남의 토큰·다른 화면                                        |

`foreign-renderer`처럼 다른 렌더러가 필요한 시나리오는 같은 실행에서 같은 종류의 탭을 둘 열고 두 번째 탭에서 `invoke`한다.

**영수증.** e2e 실행 모드의 디스패처가 `NATIVE_CHANNEL_CONTRACTS`의 채널만 `<out>/native-ipc.jsonl`에 남긴다. 기록은 호출한 뷰와 화면, 인자의 모양(토큰 값은 남기지 않음), 답 또는 오류, 그 호출로 풀린 대기다. `crates/shell/ci/e2e-check.mjs` 옆의 새 검사기가 시나리오의 단계와 이 기록을 맞춰 본다. 기대한 결과가 나온 시나리오에만 `{channel, kind: 'native-host', status: 'passed', scenarios, artifact: <그 실행의 native-ipc.jsonl>}`를 쓰고, 어긋나면 `status: 'failed'`를 쓴다. 영수증은 OS마다 따로 만든다. 한 채널이 통과하려면 Mac과 Windows 영수증이 모두 통과여야 한다. 영수증 파일은 지금의 `e2e-${{ runner.os }}` 산출물에 함께 올린다.

**소비.** `seuoffice rust`에 입력 `native_host_run`(같은 커밋의 `gate=e2e` 실행 번호)을 더한다. IPC 비교 앞 단계가 `actions/download-artifact@v4`의 `run-id`로 `e2e-macOS`와 `e2e-Windows`를 받는다. 그 실행의 `head_sha`가 이 실행의 커밋과 다르면 받지 않는다. 받은 `native-host` 영수증은 합성 영수증과 합쳐 `--native-evidence`로 넘긴다. 입력이 없거나 커밋이 다르면 native-host는 대기로 남고 단계는 실패한다. 두 워크플로를 한 작업으로 묶는 방식은 쓰지 않는다. e2e는 Mac·Windows 러너와 앱 묶음이 필요하고, rust 회차는 Ubuntu에서 돈다.

## 확인하지 못한 것

- **한컴 한글 호환.** 맥미니와 GitHub 러너 어디에도 한컴 엔진(한글, 한컴 뷰어, 한컴독스)이 없다(2026-11-17 확인). 새로 설치하거나 라이선스를 쓰는 일은 하지 않는다. 그래서 저장한 hwp/hwpx를 다른 파서로 다시 여는 검사는 **구조 검사**로만 넣고, 한컴 한글에서 배치와 표가 같게 보이는지는 **미검증**으로 둔다. 이 항목은 통과로 바꾸지 않는다. 한컴 엔진이 있는 시험 기기가 생기면 그 기기에서 파일을 열어 PDF로 내보내고 원본 렌더와 비교하는 검사를 붙인다.
- **기존 사용자의 macOS 키체인 대화상자 한 번.** 서명 정체를 고정한 첫 판(결정 0035)으로 넘어갈 때, 옛 ad hoc 판이 봉한 AI 키 항목을 처음 열면서 대화상자가 한 번 뜬다. 그 뒤 판끼리의 업데이트에서는 뜨지 않는다. 판 노트에 미리 알린다.
