# Quit lifecycle properties

Frozen from `apps/shell/src/main/index.ts:7413-7434`, `apps/shell/src/main/updater.ts:540-549`, and the native asynchronous touch-flush callback contract in `crates/shell-ipc/w/src/projects/mod.rs`.

1. A normal exit is prevented while startup is unresolved or captured recovery operations and their actual native cleanup callbacks, final session persistence, project touch flushing, owned index and folder-worker shutdown, updater will-quit, or the clean-exit marker are outstanding.
2. Duplicate exit requests while a phase is active cannot repeat project flushing or updater will-quit. Recovery cleanup, final session persistence, project cleanup and index-worker shutdown failures stop their respective phases; another explicit quit request retries the retained work. Session or project retry first re-drains native cleanup. No failure is converted to a successful drain.
3. Recovery selection closes and every captured entry/direct editor operation drains on core before final session persistence, project touch flush or worker shutdown. This keeps non-Send recovery completion and native cleanup callbacks alive until their terminal acknowledgments. Native terminal observations are delivered before cancellation, after the supervisor attempt, and immediately before workers stop. Listener delivery is not actor cleanup: the process supervisor must also be quiescent with no registered task, including the actual actor response ACK and retained core payload release. The session controller drains previously scheduled writes and the fixed-store final clean-exit plan before project flush. It does not borrow expired startup or renderer authority. Project touch flush completes before worker shutdown even after startup failure or in headless mode when Projects exists. Its settings-write failure is logged and quit proceeds, matching the original best-effort `releaseAppResources` catch; unfinished owned cleanup does not proceed. MCP actor and transport shutdown complete before index and folder-worker shutdown; both wait off core.
4. The updater will-quit runs only after worker shutdown. The clean marker runs before exit is permitted.
5. Startup failure resolves the startup barrier without relying on `Provided`. A normal ready startup resolves it only after registration, MCP start and first-window creation complete, so no startup effects begin after quit cleanup.
6. The first nonzero exit code is retained through cleanup; normal duplicate quit requests cannot replace it. Startup failure records code 1 before releasing the startup barrier, so an earlier normal quit cannot race it into a successful exit.
7. A rejected core post or discarded final-session completion is a failure, not a successful drain and not an indefinitely active session phase. The original completion has one owner across posting, starting and the asynchronous session callback. Losing that owner must enter the existing retryable failure path; retaining it must keep quit blocked until its actual result.

`tauri-runtime-cef/src/runtime.rs:2018-2020,2142-2155,3570-3571` routes both an explicit `app.exit(0)` and macOS termination through the same `RequestExit(0)` event. They cannot be distinguished by the existing event ABI. A previous requirement that only the coordinator's exact continuation event could exit was stronger than the observable contract. After cleanup, updater and clean marker have completed, an exit request with the retained exit code may proceed. An exit with a different code is prevented and the retained code is requested. No event-origin identity is claimed.

The bounded unit model in `quit.rs` represents registration, MCP start, first-window creation, startup failure, one native terminal delivery and its distinct actor ACK, recovery cancellation/drain and one failure/retry, final session persistence and one failure/retry, project flush and one cleanup failure/retry, one worker failure/retry, updater completion and duplicate events. Completed-phase counters denote idempotent logical completion, not the number of retry attempts. It abstracts OS scheduling, the actual settings writer, process termination, allocations, additional terminal events and the CEF event queue. It is source only until run on the hosted runner; it is not a model-checker proof. The supervisor regression separately keeps worker shutdown blocked between registration removal and the retry callback's real completion.
